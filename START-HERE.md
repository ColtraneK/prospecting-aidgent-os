# Start here — one guided prospecting setup

This template turns Codex into a read-only B2B prospecting assistant. You
remain responsible for every connection request and message.

## Paste this into a fresh Codex task

```text
Set up this prospecting system with me, one step at a time. I am nontechnical:
run commands yourself and tell me only the one human action I need to take now.

1. If this repository is not already open, clone
   https://github.com/ColtraneK/prospecting-aidgent-os.git into a local folder
   and work inside it. If it is already open, do not clone another copy.
2. Read AGENTS.md and follow it exactly. Run npm install, npm run init-env,
   and npm run start.
3. Help me copy the official Sheet template, create/share Google
   service-account access, bind and check my copy, store my Apify token
   locally, and sign into LinkedIn in Codex Browser myself.
4. Review my website, propose an ICP for my approval, and run a five-lead
   pilot. Add deduped public-web nominations to my Sheet immediately as
   clearly labelled Candidates, then enrich them with Apify post evidence and
   read-only LinkedIn profile verification. Do not let a Browser blockage stop
   the Candidate rows from appearing; leave their next step as verification.
5. Nothing is ever sent. Do not connect, react, comment, post, or delete
   anything. Do not ask me to run Apps Script or rebuild my Sheet. If I changed
   a column, inspect the live headers and adapt them by meaning. Keep any
   custom mapping locally and leave unmapped columns untouched. After the
   pilot, show the next-action queue and help me create the recurring local
   task.
```

You need a Google account, an Apify account, and a website or plain-language
description of your business. You will sign into LinkedIn yourself; Codex only
reads profiles and never performs outreach. Credentials, ICP data, run data,
and downloaded evidence stay in git-ignored local files. Revoke any credential
that is ever pasted into a chat, issue, or commit.
